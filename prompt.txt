1. Dynamic Target "Instant Start"
Problem: In synthetic_cam_comparison.py, the drone's position is initialized to [0, 0, -5.0]. Since $Z$ is positive-down (NED), -5.0 is interpreted as an altitude of 5 meters. The target trigger checks if altitude >= 2.0, which evaluates to True the moment the script starts, before the first actual drone telemetry is received.
Solution: Initialize self.pos to [0, 0, 0] or add a flag to ensure the target only triggers after the first valid DroneState message is received and the altitude truly crosses the 2m threshold.

2. Reversed Altitude Hold (Downward Flight)
Problem: The altitude P-controller in mission_comparison.py calculates thrust = KP_ALT * (target_alt - current_alt). In the thyra manual interface, positive thrust values map to downward velocity (NED $V_z$). When the drone is below the 5m target, it generates a positive command, driving the drone into the ground.
Solution: Reverse the sign of the thrust command: thrust = -self.KP_ALT * (5.0 - current_alt).

3. Aggressive Process Cleanup (Exit Code -9)
Problem: The start_batch_sim.sh script uses pkill -9 -f "python3". This kills all Python processes, including the ROS 2 daemon, middleware components, and the launch system itself. This causes the "Process has died" errors and can leave the environment in a broken state for subsequent runs.
Solution: Use more "surgical" pkill commands that target only specific node names (e.g., pkill -f mission_comparison) rather than the entire Python interpreter. It makes sense to keep as much open as possible and only restart the necessary scripts for the next simulation in the batch simulation "sequence".

4. QGroundControl Modal Conflicts
Problem: start_comparison_sim.sh attempts to launch QGroundControl at the start of every run. QGC has a "are your sure you want to stop the application..." thing which makes an error when the batch sh script tries to open a new one - then it just displays an error message instead of connecting to the simulation drone.
Solution: Move the QGC launch logic out of the simulation script and into the batch runner's setup phase, such that it stays open between simulation runs (if that is possible).

5. Batch Script Timeouts
Problem: The TIMEOUT and No CSV produced errors in the batch runner are a direct consequence of Issue #2. The drone crashes into the ground immediately, never completes its mission, and never triggers the _record_kpi() function.
Solution: Fixing the altitude hold and target trigger will allow the drone to complete the mission, save the CSV, and allow the batch script to proceed normally.
